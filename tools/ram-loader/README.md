# 精确版本 RK3288 RAM usbplug 读取上限修正

这是一个只处理本地文件的 Python 3 工具。它不枚举 USB、不读写开发板、不装驱动。导出目录没有 Rockchip Loader、DDR、USB 驱动或刷写器二进制。

它只接受下面这个历史上已审计的组合 BOOT 包，未知输入一律拒绝；文件名或版本号相同不能代替 SHA-256 一致。输入由使用者从有权使用的原始恢复材料中提供，本工具不下载、重分发或授权任何厂商二进制。

| 原始包内解码 usbplug v2.63（不含补零） | 87876 | `5e36a42499c4f9568234f076214d70c5e9cd047171a2262ad85c746cd76da743` |

## 用法

```sh
python3 patch_ram_readlimit.py \
  --input rk3288_loader_v1.12.263.bin \
  --output rk3288_loader_v1.12.263-readlimit16GiB-RAM-ONLY.bin

python3 selftest.py --input rk3288_loader_v1.12.263.bin
```

Windows 可以使用 `python`。仅依赖标准库。输出及同名 `.manifest.json` 必须不存在，工具拒绝覆盖；输入始终保留。输出名称必须以 `RAM-ONLY.bin` 结束，但文件名并不能替使用者阻止误刷。

**输出只能经 Rockchip 的 RAM Boot download 路径加载到内存，不能作为 eMMC 引导、Loader 分区、系统镜像或 `update.img` 写入存储。** 本目录不包含负责设备识别、RAM 下载、真实容量检查和刷写的主机工具；不会仅凭这个修正包自动开始刷机。曾经的人工操作使用 RKDevTool“高级功能”中的 Boot 行“下载”，并非“下载镜像”的分区写入流程。

## 改动与校验

这个 usbplug 版本在两条 READ_LBA 路径中用初始化字段限制读取范围，超界会返回合成 `0xCC`。初始化时 `r2 = 0x4000`，随后一条 Thumb 指令把它左移 2 位，得到 `0x10000` 个 512 字节扇区，即 32 MiB。

本工具只把解码 usbplug 偏移 `0x11bcc` 的两个字节由 `92 00` 改为 `d2 02`：`lsls r2,r2,#2` → `lsls r2,r2,#11`。新软件上限为 `0x02000000` 扇区，即 16 GiB。此指令实际运行地址为 `0x03012810`，字段地址为 `0x0301635c`。

BOOT 包的 472 usbplug 段位于偏移 14666，含补零长度 88064。解码后先核对完整 usbplug SHA、补零和周围 24 字节指令指纹，再更改两个字节、按原格式重新编码并重算包尾 CRC。CRC 使用非反射多项式 **`0x04C10DB7`**、初值 0、无最终异或；它与普通 CRC-32 的 `0x04C11DB7` 不同。本工具自行逐位计算，没有复制厂商查表代码。

最终包必须恰好只有六个变化字节：`0x15516`、`0x15517` 及包尾四字节 `0x3314a`–`0x3314d`。CRC 从 `0x6febd791` 变为 `0x2165100a`。包头、表项、471 DDR、FlashData、FlashBoot、包长、写命令及存储驱动代码保持原样。还会重新检查表项范围无重叠/空洞、payload 恰好结束于 CRC 前、编码往返一致及最终整包 SHA。

验证使用显式异常而非 `assert`，`python -O` 不能跳过输入与输出检查。selftest 覆盖精确输出、六种未知/已修改输入拒绝、CRC/结构错误、覆盖拒绝及优化模式下的拒绝行为。

## 真实容量始终是硬上限

16 GiB 是 usbplug 的软件读取限额，**不是探测到的物理容量**。使用者的主机传输程序必须在每次读写前根据刚识别的同一块设备检查：

```python
check_transfer_bounds(actual_sectors, lba, count)
```

函数拒绝非整数、负 LBA、空传输、协议计数溢出及 `count > actual_sectors - lba`，不会以增大的软件上限代替实际容量。它不执行任何传输，也不能强迫外部工具使用这项检查。历史测试板实际容量为 `0x01d1f000` 扇区，小于新上限；此数不是另一块板的默认容量。超过 16 GiB 的设备也不在这个精确修复器的验证范围内。

## 历史验证范围

历史只读核验检查了实际 RAM 指令指纹、eMMC 函数表指针和上限字段，随后在 LBA `0x2000`、`0xff80`、`0x10000`、`0x10080`、`0x20000`、`0x800000`、`0x17ff000` 各读取 128 扇区。全部不再是合成 `0xCC`，并与当时已知介质布局相符；该核验程序没有写介质或 RAM。近 32 MiB 的样本有可区分的内容；部分高地址样本相同，不能把它们解释为每个高地址的独立唯一定位证明。

以上是单块原版板、精确包及当时会话的证据，不是对所有 RK3288、所有 DDR/eMMC 或整个 16 GiB 地址空间的认证，也不是新设备可以跳过只读身份核验的理由。本次导出只重新执行离线自测，没有接触板卡。静态逆向也不能形式化证明所有潜在间接访问；输出是否正用于预期 RAM 下载路径必须由外部操作流程确认。
