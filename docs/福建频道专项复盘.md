# 福建频道专项复盘

我在这次福建专项中确认了十台正常节目，并分别完成了至少一分钟的连续实播检查。其中七台为 720p 或 1080p，两台泉州频道为 360p，厦门卫视的一条线路为 576p。这是各频道在对应测试版本和时段的结果，不能等同于所有线路长期可用。随后更换县台动态解析版本时，石狮在跨日后连接失败；晋江和德化仍通过约一分钟的检查。我修正跨日入口后，又在新版本上完成石狮和晋江各约 65 秒的连接、解码检查，但两台午夜都在播停播检验图。我保留三轮结果，区分先前正常节目、后续失败和修复后的检验图播放；两小时票据到期后的续播仍未验证。

我这次最需要纠正的判断，是把“地址有响应”“有媒体数据”“有正常节目”和“开发板能持续播放”混为一谈。现在我分别检查清单、实际片段、解码画面和开发板播放状态，只有证据覆盖到哪一步，才报告哪一步通过。

我重新读取省级官方电视目录时，只找到六台，每台只发布一条线路。福建新闻、文旅·体育和海峡卫视提供了真实的 1920×1080p25 节目，音频为 AAC 双声道。综合、东南和少儿当时返回的是 640×360 的官方版权提示片。我没有因为清单正常更新、能够解析视频或地址标着高清，就把提示片算成正常直播。福州综合、生活、少儿的另一批样本甚至具有 1080p 视频，但九张取样画面都是时段暂停提示，音轨也接近静音，仍未计入正常节目。

这些检查要求频道身份匹配、播放器处于运行状态、视频持续出帧、音轨保持运行，并在多个时间窗口内继续推进。我仍把“实际扬声器逐台听验”单独列为未完成，音轨运行不等于已经人工确认每一台的外放声音。泉州新闻综合的一段窗口有少量丢帧，因此我也没有把全部通过概括成全程零丢帧。

我在省台高清直播上遇到了一个明确的兼容性问题。原来的解码组件只接受到 H.264 Level 4.1，而这三条官方高清媒体声明 Level 5.1。开发板可以播放音频，视频却在配置阶段被拒绝。这个现象与网络取流失败不同，继续换线路不能解决组件拒绝格式的问题。

我使用原始媒体做了对照，没有转码，也没有改写视频 SPS。仅移除交给解码器的等级元数据后，指定硬件组件分别解出福建新闻 99 帧、文旅·体育 99 帧、海峡卫视 111 帧，三份有限样本均到达结束位置。这说明这些样本的实际内容能够解码，问题集中在格式接受条件。它没有证明所有 Level 5.1 视频都能播放。

我随后修订了组件的格式接受条件，继续保留图像尺寸等既有限制，再用保留原始格式元数据和 SPS 的样本验证，并完成上表三台的连续 HLS 实播。我的结论是这些已测试节目在该版本上通过，不能据此宣称支持所有 Level 5.1 的分辨率、码率或编码工具。

我也追查了莆田和仙游“先出几十帧，随后停住”的情况。它们当时返回循环版权提示片：不同片段的容器字节和清单在变化，视频载荷却重复，时间戳反复从同一起点开始。这与短播后暂停的现象相符，但我没有完成能证明唯一因果的板端对照，也不会把修正时间轴等同于恢复受限制的正常节目。这两台当时没有加入可靠节目统计。

在继续查找公开维护清单时，我又排除了几类误导线索。有的“福建新闻”“福建经济”实际只有 AAC 音频，没有视频轨和解码画面；有的“东南卫视”能解出 1080p 视频，画面却是官方时段暂停提示；另一些线路返回连接失败或明确拒绝。我没有把广播、提示片、重复地址或无法取到媒体的项目算作新增电视台，也没有尝试绕过访问限制。

石狮的后续失败暴露了另一项经验：只用白天保存的响应和一分钟实播，覆盖不到跨日行为。私有 `0528` 动态版本依赖按日期查询的当日节目记录，跨日后没有匹配到当前节目，解析器在进入播放前就失败了。那一轮石狮在 11.45 秒内报出终止错误；晋江连续播放 65.08 秒、德化 64.28 秒。我把这一轮保留为失败历史，避免后来的成功把它覆盖掉。

我对照官方分享页面使用的当前直播入口，将石狮改为读取当前栏目详情中的直播摄像项，继续核对电视栏目、当前直播状态和限制标志。原有 HTTPS、允许主机、媒体路径和票据有效期检查保留，仍使用官方返回的票据，没有自行生成票据或绕过限制。问题在于我原先把“今天的节目单里有当前节目”作为取得直播入口的前提；午夜节目单暂时没有当前项，不等于官方当前直播入口也不存在。

我先编译修订后的私有解析器，分别运行保存响应和重新取得的官方响应，每组各 50 项检查均通过。新的私有 APK 有 37 个 Java 源文件，本次只改县台辅助类；播放器分派、直播界面、Manifest 和资源保持一致，签名及内容摘要校验也通过。我将它与旧 `0528` 版本分开保存，再安装 `1386` 版本进行板测，没有把主机检查当作开发板播放验收。

我在 11 月 8 日 00:32 另行检查了石狮官方当前媒体。清单继续推进，视频为 1920×1080p25，但两张解码画面都是带石狮电视台标识的停播检验图，音轨接近静音。我把它记录为停播时段的当前官方画面，不计作新增正常节目，也不据此推翻前一轮正常节目实播的历史结果。跨日修复需要证明能够取得并播放官方当前画面；它本身不会让停播时段变成节目播出时段。

我随后在同一个已安装 `1386` 版本和运行中的 C2 组件上，重新测试了两台午夜动态入口。两台都保持一个活动连接，在三个连续观察窗口内持续出帧，视频组件为 `c2.firefly.h264.decoder`，音频组件为 `c2.android.aac.decoder`。

石狮第一次活动采样已出现 20 帧初始丢帧，末次累计为 28 帧；晋江第一次采样累计丢帧为 6，末次仍为 6。因此表中统计的是观察区间新增丢帧，不是从开台起全程零丢帧。两台截图都明确显示检验图，我只据此确认跨日后的当前入口能够连接和解码，不把这轮算作正常节目，也不增加先前十台正常节目统计。

石狮的独立官方媒体采样测得近静音（均值和峰值均约 −91 dB），这一点与停播检验图同时记录；我没有对晋江完成同样的音量测量或人工听验，不能推断它也静音。两台的 AudioTrack 在运行，只说明音轨链路工作。此次约一分钟的板测没有跨过两小时票据有效期，票据到期重新取得和连续续播、逐台实际听音、日间正常节目在新版本上的再验证和长时稳定性仍需另测。

我没有为了填满频道名称而虚构“福建公共”“福建电视剧”“福建经济生活”等当前未找到的在线直播，也没有把活动直播、景观摄像头或节目回放补成电视台。漳州、三明、南平、龙岩、宁德仍有未补齐的公开源缺口；这表示我在本轮没有验证到可用线路，并不表示这些城市没有电视节目。

我把原始地址、接口响应和诊断日志留在私有资料中。公开验证文件只保留频道、真实规格、观察时长、结果和验证边界。后续更换线路或播放器时，我会新增一轮结果，保留历史证据，避免用修复后的成功覆盖最初失败。
